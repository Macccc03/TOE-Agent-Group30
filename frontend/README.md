本模块负责 AI Agent 调用数据的展示与交互，基于 Phoenix 现有前端进行二次开发。第一阶段优先复用已有页面和组件，跑通基础查看流程；后续再完善统计图表、布局和交互体验。

## 第一阶段：基础页面

| 功能 | 基础要求 |
| --- | --- |
| 项目与调用列表 | 能进入项目、查看 Trace，展示名称、状态、耗时及可用的 Token、费用数据 |
| 调用链详情 | 能打开一条 Trace，优先复用已有调用树或时间轴组件展示节点层级与执行过程 |
| 节点信息 | 点击节点查看输入、输出、耗时、Token 和错误信息 |
| 基础反馈 | 提供加载、空数据和请求失败提示 |

第一阶段验收流程：**进入页面 → 查看调用列表 → 打开一条调用 → 选择节点 → 查看输入与输出**。优先保证流程可用，沿用已有样式。

## 技术基础与开发方式

Phoenix 现有前端使用 React、TypeScript 和 Relay/GraphQL，代码入口位于其源码的 `js/app`，包含项目、Trace 列表及调用链详情等页面。

优先复用已有实现。现有页面依赖 Phoenix 的数据层，不能将页面文件单独复制后视为可独立运行的应用。前端与后端的配合方式应随基础代码整合方案一起明确。

正式开发前，需要确定采用的 Phoenix 版本，并读取对应版本的 `AGENTS.md`、`DEVELOPMENT.md`、`.nvmrc`、`pyproject.toml`、`js/package.json` 及锁文件。

## 数据对接与职责边界

前端主要与数据处理模块对接调用链展示模型及指标数据。探针采集、建树、指标聚合、费用计算、脱敏和数据库实现由对应模块负责。

联调前需要共同明确：

- 数据提供方式：沿用 Phoenix 接口、增加适配层，或使用团队约定的本地接口。
- 列表与详情结构、Trace/Span 标识、节点类型、状态和错误返回。
- 时间字段格式、时区、相对偏移与耗时单位。
- 输入输出、属性字段及单步指标与累计指标的区别，避免重复汇总。

分工文档中的 `TraceTreeViewModel` 是设计参考，当前数据处理代码的输出字段与示例存在差异，接入前应对齐实际契约。若开发过程中先使用模拟数据，应明确标注，最终以一条真实调用链验证基础流程。
